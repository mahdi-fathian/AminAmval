# Deploy «امین اموال ناواکو» — گزینهٔ رایگان و دائمی (Render)

این سند مراحل **دیپلوی عمومیِ رایگان و همیشه‌بالا** را می‌دهد. همهٔ فایل‌های
لازم ساخته و در ریپو commit شده‌اند؛ دیپلوی فقط با چند کلیک در پنل انجام
می‌شود (نیازی به سرور و Docker محلی نیست).

دسترسیِ عمومیِ نهایی (بدون هیچ درگاه آزمایشی):

> **https://aminamval.onrender.com**

---

## گزینهٔ ۱ — Render (پیشنهادی: واقعاً رایگان، بدون نیاز به کارت اعتباری)

پیش‌نیاز: یک حساب رایگان در https://render.com (ورود با حساب GitHub کافی است).

1. ورود به پنل Render → دکمهٔ **New +** → **Blueprint**.
2. اتصال به مخزن `mahdi-fathian/AminAmval` (با دکمهٔ GitHub).
3. شاخهٔ دیپلوی: `arena/01a0bd98-aminamval`.
4. فایل `render.yaml` (در ریشهٔ ریپو) به‌خودی‌خود شناسایی می‌شود → **Apply**.
5. چند دقیقه صبر کنید؛ Render خودش تصویر را می‌سازد، سرویس رایگان را بالا
   می‌آورد و آدرس عمومی می‌دهد.

نتیجهٔ بیلد تضمین‌شده است: همین Dockerfile در CIِ GitHub ساخته، ۳۵ آزمون
کامل را گذرانده و تصویرش با موفقیت منتشر شده است.

ورود اولیه (همان مقادیر اجباری، در `render.yaml` تنظیم شده):

| نقش | نام کاربری | گذرواژه |
|---|---|---|
| مدیر | `admin` | `Admin1289@@@` |
| جمعدار | `jamdar` | `Jamdar1289@@@` |

> هر دو با «تغییر اجباری گذرواژه در اولین ورود» ساخته می‌شوند.

### نکات Render

- **Sleep:** سرویس رایگان بعد از ~۱۵ دقیقه بدون ترافیک به خواب می‌رود؛
  درخواست بعدی ظرف حدود یک دقیقه دوباره بیدارش می‌کند (داده‌ها از بین
  نمی‌روند). برای همیشه‌بیدار بودن، طرح پولی کوچک بگیرید.
- **ماندگاری داده:** دیسکِ طرح رایگان ephemeral است؛ برای ماندگاری دائمی
  داده‌ها، بلوک `disk` در `render.yaml` را فعال و `plan` را به `starter`
  تغییر دهید.
- **پورت:** اپ روی `$PORT` مشغول می‌شود؛ حالت `PREVIEW_MODE=true` کوکی‌های
  Secure را برای HTTPS فعال نگه می‌دارد.

## گزینهٔ ۲ — Fly.io (رایگانِ مشروط؛ ساخت حساب جدید به کارت بانکی نیاز دارد)

```bash
flyctl auth signup          # یک‌بار
flyctl launch               # از پوشهٔ ریشهٔ ریپو (fly.toml خوانده می‌شود)
# یا به‌صورت دستی:
#   flyctl apps create aminamval
#   flyctl volumes create amin_data --region iad
#   flyctl deploy
```

نتیجه: `https://aminamval.fly.dev` با حجم ماندگار `amin_data` در `/data`.

---

## گزینهٔ ۳ — سرور خودتان (Docker / systemd)

```bash
# Docker (همیشه بالا، حتی بعد از ریبوت هاست):
docker pull ghcr.io/mahdi-fathian/aminamval:latest
docker run -d --name aminamval --restart unless-stopped \
  -p 8080:8080 -v amin-data:/data \
  -e PREVIEW_MODE=true \
  ghcr.io/mahdi-fathian/aminamval:latest
```

دستورهای کامل systemd در `deploy/DEPLOY.md` و `deploy/README.md` آمده است.

---

## وضعیت «همیشه دیپلوی» (CI/CD)

با هر push، workflow گیت‌هاب به‌صورت خودکار:

1. سرور را در CI واقعی بالا می‌آورد و **۳۵ آزمون انتها-به-انتها** را اجرا
   می‌کند (اگر یکی fail شود، کل خط لوله قرمز می‌ماند)،
2. سپس تصویر تولیدی را می‌سازد و به
   `ghcr.io/mahdi-fathian/aminamval:latest` منتشر می‌کند.

این یعنی تصویرِ همیشه سالم و همیشه به‌روز.
